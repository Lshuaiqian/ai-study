# 功能扩展路线图

> 这份文档回答一个问题：**从现在的「小型测试版」往下走，功能上还能加什么。**
> 每条都写清：现在有什么、缺什么、动哪些模块、怎么验证、大概多大工作量。
>
> 不是功能许愿池——每一项都必须落在既有架构里，并且能想清楚「怎么证明它真的работает」。
> 工作量是**单人、熟悉本代码库**前提下的人日估算，只用于排序，别当承诺。

---

## 0. 怎么读

- 第 1 节是总览表，先看它定优先级。
- 第 2–5 节按批次详述。**每项模板固定**：现状 → 缺什么 → 要加什么 → 动哪些模块 → 怎么验证 → 工作量。
- 第 6 节讲依赖与建议顺序；第 7 节是所有扩展都要满足的验收要求。

**判断一项扩展值不值得做的标准**：它是不是补在**既有闭环的真实断点**上。
不是断点的功能（比如再加一个聊天入口）优先级一律往后放。

## 2. 第一批：把闭环补完整

### E1 真实资料 → 学习库

**现在有什么**
`library/` 下的四件套都在：`store.py`（知识原子存储）、`extractor.py`（抽取）、
`near_dup.py`（近重复检测）、`view.py`（学习库视图）。
`tools/library.py` 是命令行入口。学习库有「权威级」概念——
笔记抽出的原子是 `derived`，**不能用来判定学习者自己的笔记有错**。

**缺什么**
只灌过种子资料（`curriculum` 里的 `materials.atoms`），**从没接过真实语料**。
原子里没有出处定位，与知识点的关联也只能手工在 curriculum 里写 `knowledge_id`。

**要加什么**
1. 多格式读入：Markdown / 纯文本 / HTML / PDF / 视频字幕（`.srt`）。PDF 只取文本层，不碰扫描件 OCR。
2. **出处定位**：每个原子记 `source`（文件 + 页/段落/时间戳），判分引用依据时能指回去。
3. **自动关联知识点**：用关键词组（`keywords`）先做确定性候选，再让模型在候选里确认；
   **不许让模型自由指定**——否则原子会漂到不相干的知识点上。
4. 近重复合并：同一知识点在多份资料里重复说的，合成一条并合并出处。
5. 权威级标注：官方教材 / 官方文档 / 第三方博客 / 自己的笔记，判分权重不同。

**动哪些模块**
`library/extractor.py`（接真实语料）、`library/store.py`（出处字段 + 权威级）、
`library/near_dup.py`（跨来源合并）、`tools/library.py`（导入命令）。
新增 `library/readers/`（各格式读入，纯标准库优先）。

**怎么验证**
- 单测：同一段文字重复导入两次 → 原子数不变（幂等）；来源不同但语义相同 → 合并成一条且出处有两个。
- 确定性检查：每个原子的 `knowledge_id` 必须来自该知识点的关键词候选集，越界即失败。
- 端到端：丢进一份真实资料 → 抽出的原子能覆盖该课 80% 以上必会知识点的关键词组。
- **不许**用覆盖率数字自我表扬：原子数、合并数、越界数都要能逐个列出。

**工作量** 4–6 人日（PDF 与字幕读入各占半天，自动关联与权威级各一天，其余是测试）

### E2 苏格拉底多轮追问

**现在有什么**
`notedoctor/interrogator.py` 已经能：逐知识点判定 pass/partial/missing、
对不到位的点生成苏格拉底式追问、算出达成度百分比、把结论写进掌握度。
它还会读上一轮一键整理报出来的缺口，**优先追问那些点**。

**缺什么**
它是**一次性的**：出题 → 判定 → 结束。追问列出来就没人管了，
**没有任何地方判定「你答得对不对」**。所以现在的掌握证据主要来自
「笔记里有没有这些词」（确定性但浅），而不是「你有没有答对」。

**要加什么**
1. **答题环**：追问 → 学习者作答 → 按采分点判定（复用 `gate/rubric.py` 的结构化量规）
   → 顺着弱点继续追问，直到讲清或连续两轮无进展。
2. **作答即证据**：答对的点写成独立证据（`source: interrogation-answer`），
   与「笔记覆盖」区分开——这两者的可信度不一样。
3. **卡住判定**：连续两轮没进展 → 记成具体缺口，触发 `gate` 的 L1 补练 / L2 降粒度。
4. 追问要有**深度递进**：第一轮问概念，第二轮问边界，第三轮问对比与反例。
   不许三轮都在问同一层。

**动哪些模块**
`notedoctor/interrogator.py`（答题环与深度分层）、`gate/rubric.py`（复用采分点判定）、
`gate/mastery.py`（新证据类型的权重）、`tools/interrogate.py`（交互式循环）、
`notedoctor/tidier.py`（新证据的留痕）。
花笺侧要一个「作答区」，或者先用命令行交互跑通。

**怎么验证**
- 单测：喂一个「打得好」的回答 → 判定 pass 且升级到下一层追问；喂「背概念但答不出边界」→ 判 partial 且**在同一层再追一次**。
- 单测：连续两轮无进展 → 产生缺口且带 `stage`，不发散成无限追问（要有轮数上限）。
- 关键回归：**作答证据不能与笔记覆盖混算**——同一个知识点两条证据并存时，
  掌握度里要能看出一条是「讲过」一条是「答对过」。
- 反向测试：空回答 / 无关回答不许被判定为掌握。

**工作量** 3–4 人日

### E3 一键整理按钮接线 + 缺口写回笔记

**现在有什么**
`patches/floral-notepaper/` 里 `src-tauri/src/services/study.rs`（18.6 KB）**已经实现**：
以子进程调学习系统 CLI、逐行读 stdout 用 `app.emit` 推给前端、带超时/取消/笔记路径越界校验。
后端 `study/tools/tidy.py` 也完备：预览零副作用、四区隔离、原子写入、可回滚。

**缺什么**
**前端按钮与报告面板没做**，所以这块能力在花笺里用不了，只能开终端敲命令。
另外整理报出来的「查缺补漏」清单只显示在终端，**没有写回笔记**——
滚动一下就没了，下一轮整理/质询也看不到。

**要加什么**
1. CLI 加机器可读输出：`--json` 打 JSONL 事件流（阶段 / 报告 / 完成 / 错误）+ 明确退出码（0/1/2/3），
   GUI 不去 grep 中文报告。
2. 前端：整理按钮 + 报告抽屉（覆盖率、逐知识点状态、术语表、缺口清单）+ 取消 + 撤销本次整理。
3. **预览 → 确认两步**：整理会改真实笔记，不能点一下就改。
4. **脏 buffer 处理**：点按钮先强制保存；整理完成后比对 `updatedAt`，被改过就弹冲突对话框而不是静默覆盖。
5. 缺口清单 →「复制到我的笔记」按钮（写进「✍️ 我的笔记」区末尾）。

**动哪些模块**
`study/tools/tidy.py`（`--json` 与退出码）、`study/tools/interrogate.py`（同样加 `--json`）、
花笺侧 `src/components/MainWindow.tsx`、`src/features/study/`（新建：api / 状态机 hook / 报告面板）、
`src-tauri/src/services/study.rs`（接线与前后端契约对齐）。

**怎么验证**
- CLI 契约测试：`--json` 每一行都能 `json.loads`；四个退出码各有一个用例。
- 状态机测试：`idle→saving→previewing→confirming→applying→done/failed` 每个分支在 vitest 里可测（纯 reducer）。
- 端到端（现有脚本可直接扩）：应用后**用户区字节级不变**、AI 区整块替换不堆叠、历史只追加、预览零副作用。
- Rust 侧：非 notesDir 路径被拒、超时被杀、重复点击复用同一次运行。
- 手动场景脚本：边改边整理、整理后立刻撤销，笔记回到整理前。

**工作量** 3–5 人日（前端占大头）

## 3. 第二批：加深「掌握」本身

### E4 针对性变式练习生成

**现在有什么**
`gate/mastery.py` 的补救策略已经能判断「该练哪个知识点、该用什么手段」：
L1 补练、L2 降粒度、L3 换表征。任务则写死在 `curriculum/*.json` 里。

**缺什么**
卡住时的动作是「重做原题」或「看讲解」，**没有按薄弱点生成新题**。

**要加什么**
1. 按知识点 + 失败原因生成变式：换数据、换场景、换约束、换输入规模。
2. **变式必须可验收**：生成时同时产出验收标准与参考判定（跑机检或量规）。
3. 难度滑杆：先给「同结构换皮」，再给「换结构保考点」；连续失败就降一档。
4. 生成的东西要落盘（`state/generated/`）并进掌握度证据链，不能是即用即弃的对话。

**动哪些模块**
新增 `gate/variant.py`（生成 + 难度分级 + 验收），
`gate/mastery.py`（把 L1/L2/L3 接到变式生成），`tutor/runner.py`（跑生成的代码题）。

**怎么验证**
- 单测：对同一个知识点生成 5 道变式 → **结构必须不同**（不能是同一题换数字），且每道都带验收标准。
- 关键检查：生成的题必须**只考该知识点**，不许夹带没学过的内容（用知识点关键词做确定性校验）。
- 端到端：一个 mock 的「连续答错」序列 → 难度逐级下降、最终触发换表征，而不是无限重试。
- 不许出现「生成的题自己判自己」：验收判定必须是确定性的机检或量规，不是让生成模型自评。

**工作量** 4–6 人日

### E5 个人错题本 / 错误模式聚合

**现在有什么**
错误数据已有两处来源：`state/findings/<课>-tutor.json`（代码点评的逐行问题 + 严重度 + `knowledge_gaps`）、
`state/findings/<课>-interrogate.json`（错答、存疑、覆盖缺口）。`state/events.jsonl` 是时间线。

**缺什么**
**按知识点聚合**这件事没人做。所以「无自省」现在只有周报统计，
识别不出「你反复犯的是哪一类错」。

**要加什么**
1. 按 `知识点 × 错误类型` 聚合成档案：错误类型分事实错 / 边界条件 / 异常处理 / 命名与规范 / 概念混淆。
2. **模式识别**：同一知识点同类错误出现 ≥3 次 → 明确判定「不是不会写，是这类问题反复犯」。
3. 复习优先级：错题档案参与 `plan/review.py` 的排序，而不是均匀复习。
4. 一键回顾：把某个知识点的全部历史错误（代码原文 + 点评 + 你当时的笔记）拼成一页。

**动哪些模块**
新增 `plan/mistakes.py`（聚合与模式识别），
`plan/review.py`（错题参与排序），`plan/report.py`（周报里出「本周期反复犯的」），
`tools/plan.py`（回顾命令）。

**怎么验证**
- 单测：构造同一知识点的 4 条同类错误 → 必须判定为「反复犯」；3 条不同类型 → 不判定。
- 单测：聚合是幂等的（同一份 findings 跑两遍结果一致）。
- 关键检查：不许把「不同知识点但同类错误」误聚成一条（要能区分）。
- 反向：没有任何错误时不许编出一个「薄弱知识点」。

**工作量** 3–4 人日

### E6 间隔复习算法

**现在有什么**
`plan/review.py` 已经有 `review_queue` / `recheck_due` / `next_review` / `stage` / `reflow_count`
这一整套字段，也有优先级排序；`gate.cascade_recheck` 会做前置回炉的级联标记。
`study/tools/plan.py` 能出「今日该复习什么」。

**缺什么**
排程逻辑很薄：本质上就是「明天再来」。`stage` 没人推进，
答对答错对间隔**没有影响**——这不叫间隔复习，叫待办清单。

**要加什么**
1. 按复习结果调整间隔（SM-2 那一类）：答对拉长、答错打回并缩短。
2. 按掌握度定初始间隔：掌握度低的先密后疏，高的直接给长间隔。
3. **回炉与复习分开计**：回炉是「前置漏洞被打回」（`reflow`，打折 0.7），
   复习是「按遗忘曲线巩固」——两者语义不同，不能混在一个计数里。
4. 复习也走答题（接 E2），而不是「点一下我复习过了」。

**动哪些模块**
`plan/review.py`（排程算法），`gate/mastery.py`（`stage` 推进与掌握度联动），
`tools/plan.py`（今日视图要能解释「为什么今天该复习它」）。

**怎么验证**
- 单测：模拟一条「连续答对 4 次」的序列 → 间隔必须单调变长；中途答错一次 → 间隔打回且 `stage` 降级。
- 不变量：任何时刻同一个知识点在队列里只出现一次（不许既算回炉又算复习）。
- 边界：`next_review` 缺失的旧数据不许让排程崩（老数据兼容）。
- 可解释：今日视图每一项都要能说出排程理由。

**工作量** 2–3 人日

### E7 迁移题生成 + 结构化判定

**现在有什么**
「迁移」已经是四维之一（权重 0.2，且 `require_transfer` 默认开），
`gate/transfer.py` 在，`p0_demo` 里也有一个跑通的迁移场景。

**缺什么**
它现在只是**一个分数**：给一个固定场景，你交代码，得到 0~1 的分。
判定没有依据链，也不会按你的水平调整场景。

**要加什么**
1. **按已掌握的骨架生成新场景**：必须在不同数据集/不同结构上复用同一套请求+解析+落盘骨架。
2. **结构化判定**：给出依据——哪几行是复用骨架、哪几行是站点特定适配、
   是否把结果硬编码（硬编码直接判不通过，不是扣分）。
3. 难度分级：换站点 → 换页面结构 → 换数据形态；不通过降一档再试。
4. 判定结果进证据链（哪些行、什么理由），**不许只给一个数字**。

**动哪些模块**
`gate/transfer.py`（生成 + 结构化判定 + 难度），`tutor/reviewer.py`（复用逐行 findings 的结构化输出），
`gate/mastery.py`（迁移证据落盘）。

**怎么验证**
- 单测：给一份「真的换了站点且复用了框架」的代码 → 通过；给一份「结果硬编码」的 → **必须不通过**。
- 关键：判定必须**引用具体行号**，不接受「整体看起来不错」这种无依据结论。
- 反向：同一份代码连跑两次判定，结论必须一致（确定性；模型判定要走 `temperature=0` + 结构化输出）。
- 不许把「换了个数据集但骨架完全重写」判成迁移成功。

**工作量** 4–5 人日

### E8 学习路径动态重排

**现在有什么**
`route.json` 是静态 DAG，`system.py next` 会说「下一课是 L3」，
`system/placement-py9.json` 记录了已具备/挂账（由 `system/placement_py9.py` 生成），`graph` 能算课程与知识点状态。

**缺什么**
顺序是固定的，不会因为「你在 L4 的任务里因为文件读写卡了两次」而调整；
也不会说「L6 可以跳过，你在 L3/L4 的迁移题已经覆盖了」。

**要加什么**
1. 动态重排：结合掌握度、挂账、错误模式（E5）算下一步，**必须给出理由**。
2. **可跳过的课**：若某课的必会知识点已被后续课的迁移题覆盖通过 → 标记为可跳过（给选择，不自动跳）。
3. **建议先补的课**：某课前置知识点有挂账且未复查 → 提示先补，并说明是哪一条。
4. 路径要能导出成一页「我的学习路线」（对齐花笺里那篇「00-学习路线」）。

**动哪些模块**
新增 `plan/path.py`（重排 + 理由），`graph/builder.py`（复用状态计算），
`tools/system.py`（`next` 输出理由与可跳过项），花笺的路线笔记（重新生成）。

**怎么验证**
- 单测：给一个「L4 前置有挂账」的状态 → 建议里必须出现「先补该前置」且指明知识点。
- 单测：给一个「L6 的必会点全被 L3/L4 迁移题覆盖」的状态 → 必须标记可跳过。
- 关键：理由必须引用**具体证据**（哪次事件、哪个原子、哪条错误），不许输出「建议按顺序学」。
- 不变量：重排结果不许产生**前置未满足却先学**的顺序（用 graph 的 DAG 校验，有环或越序即失败）。

**工作量** 3–4 人日

## 4. 第三批：扩大使用场景

### E9 多学生档案

**现在有什么**
`core/config.py` 里 `state_dir` 是单一目录，掌握度、事件、发现、笔记版本全在里面。
所有工具都从这个目录读写。

**缺什么**
单档案。做不了班级、做不了对比、也没法把「我的数据」和「演示数据」分开。

**要加什么**
1. 本地多档案：`state/profiles/<档案名>/`，工具加 `--profile`（默认 `default`）。
2. 档案元信息：名字、目标考核路径、创建时间、当前课。
3. **迁移工具**：把现有的单档案无损搬进 `profiles/default/`（现有数据不能丢）。
4. 明确**不联网**：档案都在本地，符合教育场景的数据合规叙事。

**动哪些模块**
`core/config.py`（档案解析）、所有 `tools/*.py`（加 `--profile`）、
新增 `tools/profile.py`（列表/新建/切换/迁移）。

**怎么验证**
- 单测：两个档案各自写入 → 互不可见（不许串数据）。
- 迁移测试：单档案 → 多档案后，掌握度/事件/发现**逐字节一致**。
- 关键回归：默认档案的行为与现在完全一样（现有 408 个测试不许因为加了 `--profile` 而改）。
- 边界：档案名含非法字符/路径穿越（`..`）必须拒绝。

**工作量** 3–4 人日

### E10 教练端

**现在有什么**
数据层面齐了：`system.placement_report`（位置与下一步）、`graph.knowledge_status`（知识点状态）、
`plan/report.py`（周报）、E5 的错题聚合、E8 的路径。

**缺什么**
只有学习者视角。没有「谁卡在哪、共性薄弱点是什么、该干预谁」。

**要加什么**
1. 学员列表：位置、总掌握度、最近活动时间、**停滞时长**（干预信号）。
2. 共性薄弱点排行：一个班里哪些知识点普遍没过（这是教学反馈，不是个人问题）。
3. 干预建议：对停滞学员给出具体动作（补哪个知识点、用哪种手段），**要给依据**。
4. 批量操作：批量布置任务、批量看笔记质量、批量导出。
5. 权限：教练端只读学员数据 + 下发任务，**不能替学员提交**（否则门禁就没意义了）。

**动哪些模块**
新增 `tools/coach.py` + `plan/cohort.py`，复用 `placement_report` / `knowledge_status` / `mistakes`。
界面可先做命令行表格 + HTML 报告，不必一上来做 GUI。

**怎么验证**
- 单测：构造 5 个档案（分布刻意不均匀）→ 薄弱点排行与停滞名单必须与构造一致。
- 关键：教练端**不许**能写出学员的掌握度原子（写权限测试：调用后学员状态字节级不变）。
- 干预建议必须引用学员自己的数据（哪条错误、哪次事件），不许套模板。
- 空数据：没有学员时不许崩、也不许编出统计。

**工作量** 5–8 人日（取决于是否做 GUI）

### E11 整卷模考

**现在有什么**
第 9 课「模拟考核与答辩冲刺」的考核目标已入库（`career.answer`：原理 + 为什么 + 坑 + 对比）。
各课有 3–5 道自检题（每题 3 个采分点）、3–6 个任务、门禁参数。量规判定在 `gate/rubric.py`。

**缺什么**
没有「组卷 + 限时 + 判卷 + 成绩单」这个功能。第 9 课目前只是普通一课。

**要加什么**
1. **组卷**：按范围/难度/时长从各课自检题与任务里抽，可指定「只考挂账点」。
2. 限时作答与提交（超时自动交）。
3. **判卷**：逐题按采分点给分 → 汇总到知识点与四维；错题自动进复习队列。
4. 成绩单：总分 + 按知识点明细 + **哪几处是必会点没答到**（这是最有用的部分）。
5. 不许把模考成绩直接当成课程掌握度——它是**独立的一次评估**，只能作为证据之一。

**动哪些模块**
新增 `plan/exam.py`（组卷/判卷/成绩单），`gate/rubric.py`（复用），
`tools/exam.py`，花笺侧可选做一份「模考成绩」笔记。

**怎么验证**
- 单测：给一组固定答案 → 分数确定且可复现（模型判定必须 `temperature=0` + 结构化输出）。
- 关键：全答对的卷子必须 100%，全空必须 0，**不允许出现「没答也给分」**。
- 抽题检查：指定「只考挂账点」时，抽出的题必须全部命中挂账知识点（确定性校验，不靠模型）。
- 边界：题库不足时明确报错，不许悄悄少出题。

**工作量** 4–6 人日

### E12 语音答辩训练

**现在有什么**
`core/llm.py` 已支持多模态（vision），模型统一 `deepseek-flash`。
第 9 课的答辩要求是「原理 + 为什么 + 坑 + 对比」四段式，这是现成的评分维度。

**缺什么**
没有任何语音相关能力。答辩这个考核点目前只能靠写笔记间接覆盖。

**要加什么**
1. 录音 → 转文字（先接一个现成的转写服务或本地模型，别自己训）。
2. 按**四段式**评分：哪一段缺了、哪一段是背的（背的特征：复述名词但答不出因果与边界）。
3. 出追问：「你说它更快，快在哪一步？有没有反例？」
4. 逐字稿 + 评分留档，进掌握度证据（`career.answer` 的专门证据）。

**动哪些模块**
新增 `notedoctor/defense.py`（四段式评分 + 追问）与 `core/asr.py`（转写适配），
`tools/` 下加入口。

**怎么验证**
- 单测：喂四段齐全的稿子 → 四段都判到；喂只有「原理」的稿子 → 其余三段判缺。
- 关键：不许把「流利但空洞」判高分——要能识别「只有名词、没有因果」。
- 边界：空白/噪声转写结果不许给分。
- 转写是可替换模块：换服务不改评分逻辑（接口隔离测试）。

**工作量** 3–4 人日

## 7. 所有扩展都必须满足的要求

这些是项目既有约定，扩展不许破坏：

1. **预览零副作用**：只读操作不许改任何状态；写操作要有明确的确认步骤。
2. **原子写 + 失败不毁稿**：中途崩溃不留半篇文件；模型/网络失败保持原状并给人话提示。
3. **确定性优先**：覆盖率、行数、采分点命中、组卷范围这些必须是程序算的，不交给模型。
   模型只负责语义判断，且必须 `thinking=false` + `temperature=0` + 结构化输出。
4. **不编造数值**：没测量就不给分；没依据就不判错（标「待你核对」）。
5. **id 只追加不改号**：知识点 id 是历史掌握度的主键。
6. **留痕**：每个结论要能指到证据（哪个词命中、哪一行、哪次事件）。
7. **归档不删除**：清理与重建一律移走。
8. **验证纪律**：靠驱动真实代码路径验证，不靠读代码猜；
   **警惕假测试**——写了断言但恒为真的测试比没有更糟（本项目有过两次教训）。
9. **更新 `test_*.py` 与 `integrations/verify_*.py`**：新功能要么进单测，要么进端到端脚本。

## 8. 明确不做

- **不做通用聊天入口**：问答不是这个系统的核心，加了会稀释「有体系、有门禁、可追溯」的定位。
- **不做云端同步与社交**：与「本地数据、可用性优先」的取舍冲突。
- **不做题库**：题库是内容生意，本项目做的是「把考核路径变成可追踪的闭环」这件事本身。
- **不做移动端**（至少在核心闭环稳定之前）。
- **不自己训模型**：转写、判分都用现成能力，把精力放在编排与验证上。
