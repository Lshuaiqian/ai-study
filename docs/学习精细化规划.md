# 学习精细化规划

> 一句话目标：**把系统从「告诉你过没过」变成「告诉你具体差在哪一小步、下一步只练那一步」。**
>
> 这份规划与 [`功能扩展路线图.md`](功能扩展路线图.md) 是两条不同的路：
> 路线图是**加功能**（17 项），本文是**把学习这件事做细**（不加平行功能，而是提高诊断与干预的精度）。
> 两者不冲突，但**精细化优先**——粒度不细，加了新功能也只是把粗判做得更快。

---

## 0. 什么算「精细化」

不是「界面更漂亮」，也不是「反馈更长」。是可测量的三件事：

| 维度 | 粗（现在） | 细（目标） |
|---|---|---|
| **粒度** | 课程级知识点（一个点里藏着 3–4 种能力） | 可独立验证的最小能力单元 |
| **判定** | 一个分数（0.8318 < 0.85，未通过） | 分层判定 + 判据可解释 + 多次跑结论稳定 |
| **干预** | 「建议先把缺口补掉」 | 「只练异常边界这一项，用换表征的方式，两天后复查」 |

**验收标准就是能不能做到下面这句话**（现在做不到）：

> 你在「异常捕获边界」这类问题上反复失手，但「请求构造」和「限速」已经稳了。
> 下一步只练异常分支，不用重做整个爬虫。

## 1. 为什么要精细化：一个真实例子

`p0_demo` 的代码点评抓到过两条：

```
① Retry-After 既可能是秒数也可能是 HTTP 日期字符串，直接 float() 遇到日期格式
   会抛 ValueError，且这个异常不在 try 的 requests.RequestException 捕获范围内
② 只捕获了 requests.RequestException，但循环体内还有 float()、time.sleep()
   等可能抛出的非 requests 异常，这些不会被重试逻辑兜住
```

这两条是**同一个根因**：异常捕获的边界没想清楚（捕获范围与实际可能抛出的异常不匹配）。

但在现在的系统里：

- 它们只体现在 `code` 维度的扣分上，**没有落到任何知识点的证据里**；
- 第 3 课的 `K4「反爬初步：cookie/session、限速、错误重试」`是**一个点、一个分数**——
  它同时装着会话复用、限速、重试、状态码分流四件事；
- 所以系统能说「K4 没过」，却说不出**是这四件里的哪一件**；
- 于是补练只能「重做整个爬虫」，成本高、且大部分是白做。

**精细化的收益就在这里**：把 K4 拆成四个可独立判定的能力，
上面那两条点评就能精确落到「重试与退避」这个单元上，
补练范围从「整个反爬」缩到「异常边界」，一次补练十几分钟而不是两小时。

## 2. 四条主线

### A. 粒度精细化：知识点拆到可独立验证

**判据**：一个知识点如果包含「可以一个会另一个不会」的多种能力，就该拆。

反例（现在）：`K4 反爬初步：cookie/session、限速、错误重试` —— 四件事一个点。
正例（目标）：

```
K4.1 会话复用（Session 保持 cookie）
K4.2 限速与随机间隔
K4.3 重试与指数退避          ← 上面那两条点评落在这里
K4.4 状态码分流（403 与 429 的应对不同）
```

拆完的效果：能说出「K4.1/K4.2 已过，K4.3 反复失手，K4.4 没测过」。

### B. 判定精细化：分层 + 一致性 + 可解释

现在把「知道 / 会用 / 会讲 / 会迁移」压成一个 `note` 分数和四维加权。
目标是把它们**分开判定**，因为它们的可信度完全不同：

| 层次 | 判据 | 现有基础 |
|---|---|---|
| 知道 | 笔记里有没有讲到（确定性关键词） | `doctor.check_coverage` |
| 会用 | 代码里能不能跑对（机检 + 逐行 findings） | `gate/codecheck.py`、`tutor/reviewer.py` |
| 会讲 | 追问下能不能答出原理、边界、对比 | `interrogator`（只有出题，没有判答） |
| 会迁移 | 换个场景能不能复用骨架 | `gate/transfer.py` |

另外两件必须补的：

- **判定一致性**：同一份提交跑 5 次，结论必须稳定。现在**从没测过**（P0 要建基线）。
- **判据可解释**：每个结论要能指到证据（命中了哪个词、哪一行、哪个采分点没答到）。

### C. 干预精细化：给「最小下一步」

现在缺口 → 「补练」。目标是把缺口翻译成**一个具体动作**，并且动作要匹配缺口类型：

| 缺口类型 | 干预方式 | 现有基础 |
|---|---|---|
| 概念没建立 | 换表征（类比、对照、图示） | `gate` 的 L3 |
| 概念懂了但做不对 | 换数据/换场景的**变式练习** | 路线图 E4 |
| 会做但边界想不全 | 专门给**边界与反例**题 | 新增 |
| 做过但忘了 | 按遗忘曲线的**复习**（要能答题，不是点「我复习过了」） | 路线图 E6 |
| 反复犯同一类错 | **错题档案**介入，直接把历史错误摆出来 | 路线图 E5 |

**关键要求**：一次只给**一个**下一步动作。给三个建议等于没建议。

### D. 内容精细化：真实资料 + 题目层次

A/B/C 都要靠内容支撑：

- 种子资料换成**真实资料**（路线图 E1），且原子带出处定位 → 判错能引权威依据
- 自检题按**认知层次**分布（记忆 / 理解 / 应用 / 分析），而不是三道同质题
- 任务按难度**递进**，并标注它主要考哪个原子能力

## 3. 分阶段规划

### P0 · 量化基线（先量，再改）

**为什么先做这个**：没有基线，精细化就只能靠「感觉更细了」。这一步的产出是**指标**，不是功能。

做什么：

1. **判定一致性测试**：拿 `demo/` 里那两份真实提交（A 未通过 / B 通过），
   各跑 5 次完整判定，记录四维分数与结论的一致率。写进 `integrations/`。
2. **诊断颗粒度基线**：现在一次失败能定位到几个能力单元？答案大概是「课程级 = 1」，记录下来。
3. **反馈可操作性基线**：抽样现有反馈，统计其中「位置 + 改法 + 依据」三要素齐全的比例。
4. **补练成本基线**：一次「未通过 → 通过」实际花了多少时间和多少次提交（`events.jsonl` 里有数据）。

验收：四个数字出来，且能重复测（同一状态跑两次结果一致）。

工作量：1–2 人日。

> 这一步很可能暴露一个不太好看的数字——比如判定一致率不高、或反馈里带「改法」的不到一半。
> 那是好事：它是后面每一步的靶子。

### P1 · 粒度拆分（试点一门课）

**不要一次拆九门课。** 选第 3 课（它有真实提交数据可对照）做试点。

做什么：

1. 定拆分规则（见第 4 节的 id 方案）并写进 `system/` 的校验。
2. 把第 3 课的知识点按「可独立验证」重拆，每个子能力给出：名称、`keywords`、
   独立判据（哪类题/哪类检查能验证它）、与父节点的聚合关系。
3. 现有 8 条点评与 findings **按子能力重新归位**（改判定逻辑而不改历史证据）。
4. 台账跟着加：每个父知识点拆成了哪几个子节点、老的证据去哪了。

验收：

- 老 id **一个不改**，现有 `mastery.json` 里的历史原子全部仍然有效（有测试守着）。
- 同一份提交现在能定位到 ≥3 个具体子能力（对比 P0 的基线）。
- 补练范围可以缩到子能力级：给定「只有 K4.3 没过」，系统能生成只练它的任务。

工作量：3–5 人日。

### P2 · 判定分层 + 一致性

做什么：

1. 把「知道 / 会用 / 会讲 / 会迁移」四层**分开存证据**，各自有独立判据与独立的可信度。
2. 四维分数改为**由分层证据推导**，而不是直接由一次调用给出。
3. 判定一致性问题逐个定位并消除：
   - 该确定性的地方（覆盖率、机检、采分点命中）**全部改成程序算**；
   - 模型判定的部分固定 `thinking=false` + `temperature=0` + 结构化输出；
   - 仍不稳定的地方，明确标注为「不确定」而不是硬给一个分数。
4. 判据面板的数据接口（每个结论 → 证据链）。

验收：

- 判定一致率相对 P0 显著提升，且有测试固定住（低于阈值即失败）。
- 同一次提交能同时回答「哪一层过了、哪一层没过」。
- 抽查任意一个分数，能列出它的全部证据来源。

工作量：4–6 人日。

### P3 · 最小下一步

做什么：

1. 缺口 → 干预类型的映射表（第 2 节 C 表），并**只输出一个动作**。
2. 干预动作要可执行：变式练习（E4）、边界反例题、换表征（L3）、复习排程（E6）、
   错题回顾（E5）——按缺口类型选一个。
3. **闭环验证**：动作执行完后，看后续同类错误是否减少。
   这是唯一能证明「干预有效」的方式，必须有跟踪数据。

验收：

- 给定一个具体缺口，输出的下一步包含：**做什么 + 具体产物 + 为什么是它（引用哪条证据）**。
- 抽查 5 个缺口，5 个都能给出针对性的单一动作（不是「多做练习」）。
- 干预前后同一类错误的发生率有对比数据。

工作量：5–7 人日（依赖 P1 的子能力粒度，没有它就给不出精准动作）。

### P4 · 内容精细化

做什么：

1. 真实资料接入（路线图 E1），原子带出处定位。
2. 自检题按认知层次重排：每课至少 1 道「分析级」（要求对比/权衡/给反例）。
3. 任务标注「主要考哪个子能力」，并与 P1 的子能力对齐。
4. 判错时引用**权威出处**而不是模型自己说（资料权威级已经就绪，要接上）。

验收：每道题、每个任务都能说出它考哪个子能力、属于哪个认知层次；
判错能给出资料出处（文件 + 段落）。

工作量：4–6 人日（含资料整理，实际取决于资料质量）。

## 4. 关键技术难点：「只追加不改号」与「拆细粒度」的冲突

这是整个规划里最需要想清楚的一处。**现有硬约束是知识点 id 只追加、不改号**
（因为 `mastery.json` 的历史原子以 `py-agent-0X:K*` 为主键）。而精细化要拆点。

**方案：老 id 保留为「聚合节点」，子能力用 `<父>.<n>` 新增。**

```
py-agent-03:K4        保留。语义不变，降级为聚合节点：passed 由子节点聚合（全过才算过）
py-agent-03:K4.1      会话复用
py-agent-03:K4.2      限速与随机间隔
py-agent-03:K4.3      重试与指数退避
py-agent-03:K4.4      状态码分流
```

规则（每条都要有测试守着）：

1. **老 id 永不删除、语义永不改变**——历史证据全部继续有效。
2. **老证据不分给子节点**。落在父节点上的历史证据只能证明「父级曾经通过」；
   没有独立证据的子节点就是 `unknown`（**不知道就是不知道，不许推断**）。
   这一条会让拆分后短期看起来「掌握度下降了」——那是对的，它反映真实的无知程度。
3. **父节点状态由子节点聚合**，而不是独立判定：未拆点的父节点仍是独立判定。
4. 聚合规则写进 `graph/builder.py` 并测试，避免两处各算一套（本项目吃过这个亏：
   生成器与测试各算一套偏移，第二次运行就报假错误）。
5. 复习队列**只在子能力级排队**；父节点不单独排队（否则会重复复习同一个能力）。

## 5. 度量体系：怎么证明真的变细了

| 指标 | 现在（P0 要填） | 目标 | 怎么测 |
|---|---|---|---|
| 判定一致率 | 未测 | 同一提交 5 次结论一致 | 脚本跑 N 次对比 |
| 诊断颗粒度 | 课程级（≈1） | 一次失败定位 ≥3 个能力单元 | 拿同两份提交对比 |
| 反馈可操作性 | 未测 | 「位置+改法+依据」齐全 ≥80% | 抽样统计（确定性判据：有没有行号/文件名/依据字段） |
| 最小下一步命中率 | 无 | 给出单一动作 ≥90% 的缺口 | 抽查 + 干预前后对比 |
| 补练成本 | 未测 | 未通过→通过 的提交次数下降 | `events.jsonl` 统计 |

**注意**：这些指标都必须是**程序算出来的**，不能靠人工读着感觉。
尤其「反馈可操作性」——判据就是「反馈里有没有行号/文件名/依据字段」，这是确定性的。

---

## 6. 明确不做

- **不重写已经稳的部分**：整理的四区模型、门禁的挂账规矩、验证体系——这些是资产，别动。
- **不为细而细**：一个知识点拆成 12 个单元不会更有用，只会让学生面对一屏勾选框。
  判据是「能不能一个会另一个不会」，拆到这条不成立就停。
- **不追求完美一致性**：语义判定天然带噪声，目标是把**可确定的部分**抢回程序算，
  剩下的诚实标成「不确定」，而不是假装稳。
- **不在 P1 之前动九门课**：试点一门，验证了 id 方案再推广。

## 7. 与功能扩展路线图的关系

| 路线图项 | 与本规划的关系 |
|---|---|
| E4 变式练习生成 | P3 的干预手段之一，必须在 P1（子能力粒度）之后做才有意义 |
| E5 错题本 / 错误模式 | P3 的干预手段之一；它的「模式识别」依赖 P1 的子能力粒度 |
| E6 间隔复习 | 与 P3 并行可做，但队列要在子能力级（见第 4 节第 5 条） |
| E1 真实资料 | 就是 P4 的第一步 |
| E2 多轮追问 | P2 的「会讲」层，也是 P3 的干预手段 |
| E11 整卷模考 | **放在精细化之后**：模考是最粗的评估，粒度不细时它只能告诉你总分 |
| E14 知识地图 | 精细化后才有价值：节点要能显示到子能力级 |

**总的原则**：**先把诊断做细，再考虑加评估与展示。** 顺序反了会把粗判包装得更漂亮。
