# AI 辅助学习系统 · 项目说明

> 一个把「自主学习的五无」变成可执行闭环的学习系统。
> 当前阶段：**小型测试版已跑通**（单课掌握闭环可复现），距离日常可用还差一步。
>
> 这份文档面向准备加入或接手的人：既讲**已经实现的功能**，也讲**为什么这么设计**。
> 后半部分是给开发者的（架构、约定、验证、路线图）。

## 0. 三分钟速览

**一句话**：输入你的情况、目标、资料和考核路径，系统把它变成一套有知识体系的课程，
用任务驱动你写代码、AI 点评改正、你写笔记、AI 整理并质询查缺补漏，
达标才允许进下一课——**必须完全掌握**。

**它解决什么**：自学最难的从来不是找不到资料，而是这五件事没人管——
无目标、无规划、无体系、无自省、无人指导。

**现在能跑什么**（都已验证，不是设计稿）：

| 能力 | 状态 |

| 自上而下：知识体系 → 拆课 → 9 门课完整内容 | ✅ 9 门课 / 56 个知识点 / 图无环 |

## 1. 我为什么做这个（设计意图）

这一节是这份文档最重要的部分。**功能可以重写，下面这些判断我不想被改掉**——
如果某个实现跟它们冲突，那是实现错了。

### 1.0 服务对象：学生个体

> **这是一个服务学生个体的个性化学习系统。** 不是给学校或机构用的教学管理平台。
>
> 所有功能只回答一个问题：**「我（学生本人）现在该做什么、凭什么说我不行」。**

这条定位决定了很多取舍，凡是冲突的一律不做：

- **不做教练端 / 教师端**：没有学员列表、没有班级视图、没有批量布置、没有共性薄弱点排行。
  这类功能的前提是多用户 + 权限 + 机构视角，与本项目「个人、本地、可信」的取舍直接冲突，
  真做起来还要额外背上账号体系与教育场景的合规——那是**换一个产品**，不是加功能。
- **不做多用户与协作**：数据是本人的、在本机。这不是暂时的技术限制，是刻意的选择：
  学习记录是敏感的个人数据，不出本机是最简单的合规，也是可信度的一部分。
- **不做社交与排行榜**：会诱导刷分，与下面 §1.2 的「必须完全掌握」直接冲突。

### 1.1 起点：自学失败的五个位置

我用「五无」来定位问题，每一无都对应一个必须存在的机制：

| 痛点 | 具体表现 | 对应机制 |
|---|---|---|
| **无目标** | 学什么全凭当下兴趣，三天换一个方向 | 目标来自**外部考核路径**，不靠自己拍脑袋 |
| **无规划** | 不知道今天该干什么、下一步是什么 | Planner：体系拆课 + 位置感知的下一步 |
| **无体系** | 知识点是散的，学完连不成网 | 自上而下：先建体系，再拆课；每课先声明知识点 |
| **无自省** | 不知道自己涨没涨、卡在哪 | 事件日志 + 周报 + 复习回炉 |
| **无人指导** | 写错了没人看，笔记写得烂没人说 | AI 点评 / 质询 / 整理与指错 |

### 1.2 三条不肯让步的原则

**① 必须完全掌握，不接受「大概会」。**

门禁是四维加权，**每一维**都有下限，必会知识点覆盖率必须 100%：

```
掌握度 = 0.35·代码 + 0.25·测验 + 0.20·笔记 + 0.20·迁移
门槛：总分 ≥ 0.85 且每一维 ≥ 0.6 且无致命误解 且必会覆盖 100%
```

「迁移」单独占一维是刻意的：**能在原题上跑通不算掌握，能换个场景复用才算。**
我见过太多「教程跟着敲一遍就会了」的假象。

同时留了一个逃生阀：真的卡住的点允许**带疑点前进（挂账）**——
但挂账必须**留痕**，下一课开头必须复查。挂账不等于忘记。

**② 笔记是学习循环的一部分，不是副产品。**

大多数人把笔记当"课后可选动作"。这里的笔记直接影响能不能进下一课（占 20%），
而且 AI 会把笔记当成判断你懂没懂的证据来源之一。

**③ AI 可以提问、可以指错，但不许替学习者下结论。**

这条最容易被实现成相反的样子，所以我写得很具体：

- **无依据不许判错**：AI 觉得有问题但找不到依据时，只能标「待你核对」，不能判错。
- **不许编造数值**：没有测量数据就不给分（笔记维度返回 0），而不是"没发现错误所以满分"。
- **不知道就是不知道**：学习位置里 `unknown` 不等于 `met`。
- **AI 不能给自己打分**：AI 整理出来的稿子绝不能被当成学习者自己的笔记去算覆盖率——
  否则整理一次覆盖率就到 100%，掌握度虚高。

### 1.3 一个反直觉的决定：不重新造一个笔记应用

笔记这块我直接**连接现有的花笺（floral-notepaper）**，而不是自己写一个。

理由：笔记应用的真正难点是编辑体验、双链、搜索、同步——那是另一个产品。
我需要的只是「AI 能读能写一批 Markdown 笔记」，而这正好是花笺已经做好的部分。
花笺的笔记就是普通 Markdown + 一份 JSON 索引，直接读写目录即可，连插件都不用写。

我只给花笺补了它缺的两块：**多级分类（文件夹）**和**便签墙**。

### 1.4 目标来自外部考核

选的第一个目标是西二在线的 `learn-AI` 考核路径。原因：
它的要求足够具体（有作业清单、有自检题），而且是**别人定的**——
这样"要不要学这个"就不由我当下的兴趣决定。

课程内容以它的**考核要求与任务**为准，不做入门科普式的泛泛介绍。
起点假设是已有 C/C++ 基础，所以课程可以直接对标讲解。

## 2. 核心闭环（S4 定案）

这是整个系统的骨架，所有功能都是为它服务：

```
① 用户给定：学习情况 + 目标 + 资料 + 考核路径
        ↓
② 资料整合成「学习库」（知识原子，可追溯到出处）
        ↓
③ 主题课程：先声明本课知识点（知识点能串联成体系，不是孤岛）
        ↓
④ 推荐课程（按体系顺序 + 学习者当前位置）
        ↓
⑤ 任务驱动（每课有可验收的产出）
        ↓
⑥ 写代码 → AI 点评 → 改正（在真实代码上迭代，不是看讲解）
        ↓
⑦ 更新笔记 → AI 加工、指错、并联系相关知识
        ↓
⑧ 笔记达标后 → 进入下一课
```

**这一圈里最容易被做歪的是 ⑦，所以单独说清楚它现在的样子：**

```
你在花笺里写笔记
   ↓ 一键整理（AI 把碎片改写成教材级复习稿，放进「🤖 AI 整理」区）
   ↓ AI 质询（逐点判定 + 追问 + 达成度%，结论写进掌握度）
   ↓ 下一轮整理/质询会带上上一轮报出来的缺口
```

整理和质询是**双向闭环**，不是两个独立工具：

- 整理发现的缺口 → 存进 `findings/`，**下一次质询优先追问这些点**（实测会打印「带入上一轮整理的 N 个缺口」）
- 质询的结论 → 写进掌握度，门禁与 Planner 读得到

### 3.2 课程体系（9 门课，56 个知识点）

**骨架是老 9 课**，内容用西二考核**追加补充**而成。为什么不用西二的课表当骨架：
进度、掌握度记录、导师课程表都绑在老课 id 上，换骨架等于把这些作废。

| 课 | 标题 | 知识点 |
|---|---|---|
| L1 | Python 语法速览 + 面向对象（C/C++ 对照） | 10 |
| L2 | 网络基础与 HTTP/JSON | 5 |
| L3 | 网络爬虫（对标 west2 Task2） | 7 |
| L4 | 数据分析与统计描述 | 4 |
| L5 | 可视化与报告 | 4 |
| L6 | 项目整合 | 5 |
| L7 | 顶层 AI 应用 - LLM API 与提示工程 | 8 |
| L8 | Agent 与 Function Calling | 5（自撰，西二没覆盖） |
| L9 | 模拟考核与答辩冲刺 | 8 |

每门课都齐备：知识点（含 `keywords` / 前置依赖 / 对比 / 应用去向）、
**3 道自检题 × 每题 3 个采分点**、**3–6 个可验收任务**、
每个知识点至少一条种子资料、门禁参数。

### 3.3 花笺集成

| 功能 | 说明 |
|---|---|
| 连接花笺 | 直接读写笔记目录 + 维护它自己的 `metadata.json`（写前备份） |
| 自动建课 | 课程主文件夹 + 「00-学习路线」+「01-知识体系」+ 每课一篇子笔记 |
| 笔记结构 | **考核要求写在最上面**，然后才是「✍️ 我的笔记」 |
| 排序 | 按课序排列，不混乱（花笺是按修改时间倒序，所以要反向设定时间戳 + 文件 mtime） |
| 重建 | 换骨架时归档旧笔记（**不删除**），只动课程文件夹，使用者自己的笔记一律不碰 |
| 多级分类补丁 | 花笺原本只有单层分类，已补 |
| 便签墙 | 新增的浏览视图 |

### 3.4 一键整理的写入语义（这块被问过，专门说清）

**不是覆写，是分区管理：**

| 区 | 谁写 | 多次操作的行为 |
|---|---|---|
| `## ✍️ 我的笔记` | 使用者 | **AI 永不改动**（字节级不变） |
| `## 🤖 AI 整理` | 一键整理 | **整块替换**，幂等 |
| `## 🧪 AI 质询` | AI 质询 | **整块替换**，与整理区互不吞并 |
| `## 📚 整理历史` | 程序 | **只追加**，可回滚 |

由此得到几个硬保证（都有端到端断言）：

- **不许越整理越长**：反复整理后 AI 区标题恒为 1 份、结构分隔线不增长
- **预览零副作用**：不加「确认」时不写笔记、不改掌握度、不塞复习队列
- **可回滚**：每次整理的整理稿留底
- **失败不毁稿**：断网/模型失败时笔记原样，给人话提示而不是崩溃栈
- **写入原子**：先写临时文件再替换，中途崩溃不会截断笔记

### 3.5 导师侧

- `lessons.json`：**9 课课程表**，由体系自动导出（含知识点、作业、自检题）
- `progress.json`：由学习位置推导，当前 `current_lesson = 3`
- 支持图片识别（做题/报错截图直接丢给导师）
- 导师的交作业结果会桥接回学习系统（`study/state/`）

### 4.2 单一真源与派生关系

这是整个项目最重要的一张图。**动手改数据之前先看清谁是源头：**

```
        西二体系（内容来源）
    west2-ai-2026.json + placement-west2.json
                │
                │  bridge/*.json（人工撰写：哪一点归到哪一课）
                │  bridge/_index.json（台账：每个西二点必须有归宿）
                ▼
        merge_py9.py（生成器：只追加不改号 + 台账校验 + 建图自检）
                │
                ▼
    route.json + curriculum/py_agent_0*.json      ← 从这里往下都是派生
                │
                ├──► graph/（课程 DAG + 知识点 DAG，做环检测与级联复查）
                ├──► 花笺笔记（rebuild_huajian.py 建课）
                ├──► 导师课程表（export_tutor_lessons.py）
                └──► 单课闭环 / 门禁 / Planner
```

**规矩：派生物一律不手改。** 手改派生文件的结果是下次生成就被覆盖，
更糟的是两份数据开始漂移而没人发现。

### 4.3 关键数据文件

| 文件 | 内容 | 谁写 |
|---|---|---|
| `state/mastery.json` | 掌握度：知识点原子（`py-agent-0X:K*`）+ 课程四维 | 门禁、整理、质询 |
| `state/events.jsonl` | 事件日志（append-only），自省与周报的底座 | 各环节 |

| 花笺 `metadata.json` | 花笺自己的笔记索引 | 花笺 / 建课工具（写前备份） |

## 5. 怎么跑

```bash
# ---------- 看体系 ----------
python study/tools/system.py check            # 体系校验
python study/tools/system.py next             # 当前该学哪一课、缺什么
python study/tools/system.py placement        # 我在哪、走过多少、卡在哪
python study/tools/system.py show <course_id> # 看某一课的知识点

# ---------- 复现单课掌握闭环（会真的调模型，约 0.03 元）----------
python study/p0_demo.py                       # 沙箱运行，不动真实状态
python study/p0_demo.py --keep-state          # ⚠️ 会写真实状态

# ---------- 笔记 ----------
python study/tools/rebuild_huajian.py         # 预览：要在花笺建哪些笔记
python study/tools/rebuild_huajian.py --apply # 执行（旧课程笔记先归档）

# ---------- 一键整理 ----------
python study/tools/tidy.py --course py-agent-04              # 预览（零副作用）
python study/tools/tidy.py --course py-agent-04 --apply      # 确认写入
python study/tools/tidy.py --course py-agent-04 --soft       # 只排版，不调模型
python study/tools/tidy.py --course py-agent-04 --versions   # 看历史版本
python study/tools/tidy.py --course py-agent-04 --rollback <时间戳>
```

## 6. 工程约定（新加入者必读）

这些约定不是风格偏好，**每一条都是踩过坑之后加的**，违反它们会引入静默错误。

### 6.1 数据

- **单一真源**：真源只有 `route.json` / `curriculum/` / `bridge/` / 西二体系四类；
  其余（图、笔记、课程表、位置桥接）都是派生，**不手改**。
- **知识点 id 只追加、不改号**：`py-agent-0X:K*` 是历史掌握度记录的主键，
  改号会让所有历史记录失配。新知识点顺号接在后面。
- **每个知识点必须有归宿**：要么被已有知识覆盖、要么新增、要么**显式排除并写理由**。
  三者必居其一，有台账强制校验。
- **每个知识点必须有 `keywords`**，否则它在确定性覆盖判定里永远不可能被算作覆盖。
  `keywords` 的语义是「每个组内任一词命中即该组通过，所有组都通过才算覆盖」。
- **每个知识点至少一条种子资料**，否则学习库与笔记体检对它是空的。
- **两个 id 空间不许混**：体系级 id（`net.http`）与本课本地 id（`K1`）混在一个字典里，
  会导致匹配永远失败、且**静默**。（这个坑真踩过：挂账点因此全部失去保护。）

### 6.2 写入

- **预览零副作用**：只读操作不许改任何状态。加 `--apply` 才写。
- **原子写**：先写临时文件再 `os.replace`，中途崩溃不留半篇文件。
- **失败不毁稿**：模型/网络失败时保持原状，给人话提示，不抛栈。
- **区域隔离**：AI 只写自己的区，使用者的内容字节级不动。
- **归档而不是删除**：重建、清理时一律移走，不删。
- **只动自己该动的地方**：例如重建花笺笔记时只碰课程文件夹，使用者其他笔记不碰。

### 6.3 语义

- **没写到 ≠ 没掌握**：整理/质询发现"笔记里没写到"某个知识点时，不许直接判未通过。
  已有证据的（已通过、或学习位置判定已具备/挂账）只挂「待复核」，不摘牌。
- **不知道就是不知道**：没有测量就不给分；没有依据就不判错，标「待你核对」。
- **不编造数值**：不许为了凑分写标记位，不许用 1.0 代替"没测过"。

### 6.4 验证纪律（最容易被忽视，但最重要）

- **靠驱动真实代码路径来验证，不靠读代码猜**。跑一遍真流程，看真输出、真文件。
- **优先确定性程序检查，不要相信模型自述**。判分、覆盖率、行数这些必须是确定性的。
- **把「还差什么」变成会失败的测试**，而不是写在注释里。
  例：空壳课程台账、知识点归宿台账、生成器自检。
- **每个结论都要能指到证据**（哪一行、哪个文件、哪次运行的输出）。
- **警惕假测试**：写了断言但恒为真的测试比没有测试更糟。
  本项目有两次教训：
  - 一条"覆盖率不会被 AI 稿抬高"的测试，输入文本里直接拼了关键词，永远通过；
  - 一条想用"文字相似度"发现重复自检题的测试，实测两道语义相同的题相似度只有 0.058，
    根本抓不住——最后改用**数量不变量**才真正拦住它。

## 9. 技术选型与依据

### 9.1 模型

- **统一 `deepseek-flash`**，包括图片识别——不必为了看图换模型
- **思考模式默认关闭**：开着会忽略 `temperature` 并吃掉约 75–79% 的输出预算
- 判分/体检/覆盖这类调用必须 `thinking=false` + `temperature=0`，保证可重复
- 结构化输出统一走 **JSON Output**，判分走**结构化量规**而不是让模型自由发挥
- 成本可见：每次调用报告命中/未命中/输出 token 与估算花费
  （单课闭环演示约 11 次调用 / 0.03 元）

### 9.2 为什么内核是 Python 且只用标准库

- 学习内容本身就是 Python，工具链同语言便于互相验证
- 只用标准库 → 别人 clone 下来就能跑内核与全部测试，不需要配环境
- 第三方依赖（`requests` / `bs4` / `pandas`）只在**学习任务**里需要，不影响系统运行

### 9.3 为什么花笺用 Tauri

花笺（floral-notepaper）是 Tauri 2 + React + TypeScript 的笔记应用，MIT 协议。
选它而不是自己写：见 §1.3。

**我们对花笺的改造以补丁形式提供，不在本仓库里放源码副本**：见
[`patches/floral-notepaper/`](patches/floral-notepaper/)。

补丁只有 66 KB，而上游完整副本 6.25 GB（`src-tauri/target/` 构建目录占了 6 GB），
而且它是别人的项目——整份塞进来会让仓库体积失控、许可证归属混乱，
上游一更新还会产生大面积无意义 diff。补丁可读、可审、可选择性应用。

补丁内容是：**多级分类（花笺原本只有单层）** + **便签墙** +
「一键整理按钮」的 Rust 侧（已实现但未接线）。改动集中在 3 个手写文件 + 1 个新模块，冲突面小。

### 11.1 无关项目已经用 .gitignore 排除

本机的开发目录里**同时**装着一个跟本项目无关的东西：

`refs/`（花笺源码与西二资料的副本，一万六千多个文件）同样排除——
那是别人的仓库，用 submodule 或在文档里给来源链接。

**想彻底分家**（推荐，比 ignore 干净）：把那些路径整体移到另一个目录，再删掉 `.gitignore` 里对应的那一段。

```bash
# 在仓库根执行（会把 Java 项目原样搬到同盘另一个目录）
mkdir ../bookshare-platform
mv src out web data build.bat run.bat clean.bat README.md ../bookshare-platform/
```

> 根 `README.md` 已经是本文档。那个 Java 项目的说明已改名为 `README-bookshare.md`
> （同样在 `.gitignore` 里），跟它一起搬走即可。

### 11.2 密钥（这条没得商量）

本机 `E:\Agents\python-tutor\config.json` 里有一把**真实可用的 API key**。
它目前不在这个仓库里（那是另一个目录），但有两个风险必须处理：

1. `study/core/config.py` 的密钥解析顺序是
   `study/config.json` → 环境变量 `DEEPSEEK_API_KEY` → `E:\Agents\python-tutor\config.json`。
   **最后那是一条写死的绝对路径兜底**——别人 clone 下来跑不通，
   而且一旦有人本地复制了这个文件，它就会进仓库。
   **应该改掉**：改成相对路径或纯环境变量，别在代码里写死别人机器上的位置。
2. 仓库根已有 `.gitignore`（`study/config.json`、`*.key`、`.env` 等都在里面），
   但**别只靠它**——密钥不该出现在工作区里。
