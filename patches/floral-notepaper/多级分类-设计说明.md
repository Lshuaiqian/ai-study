## 1. 现状（已核实）

| 项 | 现状 |
| --- | --- |
| 存储 | `<notesDir>/<分类>/<id>_<标题>.md`；未分类直接在 `<notesDir>/` 根 |
| 分类模型 | `NoteMetadata.category: String` —— **单个字符串，只有一层** |
| 写路径 | `note_path_in_category()`：`notes_dir.join(category).join(file_name)` |
| 扫描 | `rebuild_metadata()` 只遍历 `notes_dir` 的**一层**子目录；`scan_dir_for_notes()` **遇到子目录直接跳过**（只收 `.md`） |
| 分类 CRUD | 已有 `create_category` / `rename_category` / `delete_category` / `move_note_to_category` |
| 分类名校验 | `create_category` / `rename_category` 明确拒绝 `/`、`\`、`:`、`..` |

**关键发现**：写路径用的是 `PathBuf::join(category)`。Rust 在 Windows 上同样把 `/` 当分隔符，
所以 **`category = "工作/2026"` 现在就能写到 `notes/工作/2026/x.md`**——
存储层不用改，改的是「扫描」和「校验」两处。

### 2.2 放行 `/`，但仍拦住路径穿越

新增一个归一化函数（放在 `impl AppError` 之后、`NoteStore` 附近即可）：

```rust
/// 归一化分类路径：允许 "工作/2026" 这样的多层写法，
/// 但拒绝空段、"."、".." 以及 Windows 非法字符，防止写出 notesDir 之外。
fn normalize_category(name: &str) -> Result<String, AppError> {
    let name = name.trim().replace('\\', "/");
    let name = name.trim_matches('/');
    if name.is_empty() {
        return Err(AppError::category_name_empty());
    }
    let mut parts = Vec::new();
    for part in name.split('/') {
        let part = part.trim();
        if part.is_empty() || part == "." || part == ".." {
            return Err(AppError::category_name_invalid_chars());
        }
        if part.contains([':', '*', '?', '"', '<', '>', '|']) {
            return Err(AppError::category_name_invalid_chars());
        }
        parts.push(part);
    }
    Ok(parts.join("/"))
}
```

然后把三处校验换成它：

```rust
pub fn create_category(&self, name: &str) -> Result<(), AppError> {
    let name = normalize_category(name)?;                 // ← 改这里
    let path = self.notes_dir().join(&name);
    fs::create_dir_all(&path)?;
    Ok(())
}

pub fn rename_category(&self, old_name: &str, new_name: &str) -> Result<(), AppError> {
    let new_name = normalize_category(new_name)?;         // ← 改这里
    ...
}

pub fn move_note_to_category(&self, id: &str, new_category: &str) -> Result<NoteMetadata, AppError> {
    let new_category = if new_category.trim().is_empty() {
        String::new()                                     // ← 空 = 移回根目录
    } else {
        normalize_category(new_category)?
    };
    ...
}
```

> `rename_category` 里 `old_name` 的查找、以及 `delete_category` 的
> `notes_dir.join(name)` + `canonicalize` 越界检查，都按同样的相对路径语义工作，
> 无需额外改动；但 `delete_category` 建议顺带确认 `canonicalize` 结果仍在 `notes_dir` 内
> （源码里已有这个安全检查，保留即可）。

### 2.3 一个已存在的隐患（顺手修）

`scan_dir_for_notes` 在 rebuild 时用**文件 mtime** 当 `created_at` / `updated_at`，
所以 `metadata.json` 损坏重建后，**真实创建时间会丢失**。
如需保留，可改用文件名里的 id + 一个 sidecar 时间戳，或接受现状并在 UI 上不展示"创建时间"。

### 2.4 `list_categories` 也必须递归（实现时才发现）

改前它只遍历 `notes_dir` 的**一层**：

```rust
for entry in fs::read_dir(&notes_dir)? {
    let entry = entry?;
    if entry.path().is_dir() {
        categories.push(entry.file_name().to_string_lossy().to_string());
    }
}
```

多层分类下 `notes/工作/2026/` 会被漏掉，前端拿不到子分类。改为递归收集 + 返回完整相对路径，并新增：

```rust
fn collect_categories(dir: &Path, prefix: &str, out: &mut Vec<String>) -> Result<(), AppError> {
    for entry in fs::read_dir(dir)? {
        let entry = entry?;
        if !entry.path().is_dir() { continue; }
        let name = entry.file_name().to_string_lossy().to_string();
        if name.starts_with('.') { continue; }
        let current = if prefix.is_empty() { name } else { format!("{prefix}/{name}") };
        out.push(current.clone());
        collect_categories(&entry.path(), &current, out)?;
    }
    Ok(())
}
```

> 行为：**中间层级也会返回**（`["A", "A/B", "工作", "工作/2026"]`），
> 因为前端建树需要每一层。这是刻意的。

### 2.5 修掉一个真实漏洞：`create_note` / `update_note` 不校验分类

这是实现过程中发现的**既有安全问题**（不是本次改动引入的）：

```rust
// create_note 改前
let category = request.category.clone();          // ← 直接信前端
let note_path = self.note_path_in_category(&file_name, &category);
```

`note_path_in_category` 做的是 `notes_dir.join(category)`，所以
**`category = "../外面"` 就能把笔记写到 notesDir 之外**。`update_note` 同样。

修法：新增「可选分类」归一化（空串 = 未分类，合法），三处入口统一走它：

```rust
pub(crate) fn normalize_optional_category(name: &str) -> Result<String, AppError> {
    if name.trim().is_empty() { Ok(String::new()) } else { normalize_category(name) }
}
```

```rust
// create_note
let category = normalize_optional_category(&request.category)?;
// update_note
let new_category = normalize_optional_category(&request.category)?;
// move_note_to_category
let new_category = normalize_optional_category(new_category)?;
```
