# 迁移题说明 · t_py03_3

## 我换了什么
原练习爬的是 books.toscrape.com（书列表，`article.product_pod`），
我换成 quotes.toscrape.com（名言列表，`div.quote`）。两个站点的 DOM 结构和
数据字段完全不一样：一个是 标题/价格/星级，一个是 名言/作者/标签。

## 我改了三处
1. **目标站与起始 URL**：`START` 换成 quotes 站的第一页。
2. **解析器**：新写了 `QuotesParser`，改成抽 `span.text` / `small.author` /
   `a.tag`。原练习里我是用 `_grab` 状态机抽价格的，这次抽标签是列表，
   所以在 `handle_data` 里改成 append 而不是累加字符串。
3. **翻页**：原练习的翻页是 `li.next > a`，这个站居然也是 `li.next > a`，
   所以我复用了 `NextLinkParser`，但重新确认过确实是同一个结构才用的。

## 我**没有**改的（因为跟站点无关）
- `polite_wait()` 的限速逻辑（1s + 随机抖动）
- `fetch()` 的指数退避、403/429 分支处理
- `save_json()` 的落盘方式

## 结果
跑到第 2 页，20 条，字段齐全（名言 20 条 / 作者 20 条 / 标签 62 个）。
整体耗时约 3 秒，没有触发限频。

## 我的体会
真正能复用的是"请求 + 限速 + 重试 + 落盘"这套骨架，解析部分基本每次都要重写，
因为 DOM 结构是站点特定的。之前我以为爬虫代码能整个搬过去，实际不行。
